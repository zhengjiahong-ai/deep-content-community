# 研究计划

> 版本：v1.0（初始版）  
> 日期：2026-11-07  
> 当前阶段：需求验证准备

## 1. 研究目标

验证“深度内容消费后的个人思考与小规模讨论”是否构成真实、可重复且值得解决的问题，并判断现有产品组合为什么可能不足以满足用户需求。

研究不以证明既定产品构想为目标。若证据表明用户没有明显痛点、已有工具组合足够，或用户不愿增加新的使用入口，应如实缩小或调整产品范围。

## 2. 核心研究问题

| 编号 | 研究问题 | 希望获得的证据 |
| --- | --- | --- |
| RQ1 | 用户通常在什么时候产生值得保存或继续讨论的观点？ | 最近一次真实经历、具体内容、发生时点 |
| RQ2 | 用户如何保存片段、原始出处和自己的想法？ | 实际工具、操作步骤、遗漏和失败案例 |
| RQ3 | 用户之后能否找回并重新使用这些思考？ | 检索行为、回顾频率、真实使用场景 |
| RQ4 | 内容平台评论与个人笔记之间是否存在具体断点？ | 用户当前工作流、跨平台切换成本和替代方案 |
| RQ5 | 用户是否愿意围绕具体片段参与小规模讨论？ | 过去参与讨论的行为、讨论对象、规模与顾虑 |
| RQ6 | 用户为什么会或不会增加一个独立工具？ | 采用门槛、使用频率、可替代性和付费判断 |

## 3. 第一轮用户访谈

### 3.1 样本招募

建议完成 8—10 位半结构化访谈，其中至少一半优先考虑小宇宙重度用户。

初始筛选条件：

- 最近一个月有稳定的深度内容消费行为，例如每周收听至少两期 30 分钟以上的播客，或持续阅读非虚构书籍、深度文章；
- 并且曾经收藏、截图、写笔记、发表评论或分享内容；
- 能够讲述最近一次具体经历，而不是只表达抽象兴趣。

样本应覆盖播客用户和深度阅读用户，避免最后只研究单一平台用户。样本数量用于课程阶段的探索性定性研究，不代表统计意义上的总体抽样。

### 3.2 访谈问题建议

优先询问过去行为，不先展示产品概念：

1. 最近一次让你觉得“这段内容值得记住”的经历是什么？当时看/听的是什么？
2. 你当时做了什么？有没有暂停、截图、收藏、记笔记、评论或转发？
3. 你保存的是原文/时间点，还是自己的理解？两者是否放在一起？
4. 之后你有没有再次寻找这段内容？怎么找的？成功了吗？
5. 你是否曾想和别人继续讨论某个具体观点？最后在哪里讨论、为什么？
6. 你现在使用哪些工具完成这些事情？它们哪里顺手、哪里麻烦？
7. 有没有发生过“记得观点但找不到出处”或“收藏了却再也没打开”的真实例子？
8. 如果不再增加任何新工具，你会继续怎样处理这个问题？
9. 对一个新的独立工具，你最不能接受的额外操作是什么？

避免直接问“你会不会使用我们的产品”或用功能描述诱导受访者表示赞同。必要时在访谈后半段展示原型，再观察任务表现。

### 3.3 记录格式

每位受访者使用匿名编号（如 U01），记录：

- 基本筛选条件（不记录不必要的身份信息）；
- 最近一次真实事件及上下文；
- 当前行为流程和使用工具；
- 具体困难、频率和后果；
- 现有替代方案；
- 对新工具的顾虑；
- 反例和与初始假设不一致的证据。

未经许可不保存可识别的录音或个人敏感信息。

## 4. 竞品体验研究

先完成小宇宙的完整体验，再按相同任务检查辅助竞品。

### 核心竞品：小宇宙

需要实际核验：

- 内容发现、订阅和收听的主要流程；
- 时间点评论、评论回复和高能片段等互动能力；
- 收藏、节目/单集信息和个人内容管理；
- 创作者、品牌合作、广告、付费内容或会员等商业模式线索；
- 用户从听到观点到表达、保存和再次找回的实际操作成本。

不能把“小宇宙没有评论区”或“小宇宙无法进行时间点讨论”作为研究前提。

### 辅助竞品

- **Snipd：**观察播客高亮、转录、摘要、搜索及向外部知识工具同步的流程；
- **Readwise：**观察多来源摘录汇集、复习和知识回顾；
- **flomo：**观察轻量记录、标签/关联和回顾；
- **豆瓣：**观察围绕书籍、主题和兴趣形成的讨论及内容评价。

所有竞品功能和价格均应在实际体验或官方页面中重新核验，并记录核验日期。历史研究报告中的产品信息不能自动视为当前状态。

## 5. 初步验证流程

### 阶段 A：需求发现

- 完成 8—10 位目标用户访谈；
- 梳理 3—5 条典型用户旅程；
- 区分高频痛点、低频但高价值需求和纯粹偏好；
- 整理支持与反对产品假设的证据。

### 阶段 B：问题与竞品对照

- 完成小宇宙核心流程体验；
- 完成 Snipd、Readwise、flomo 的相关任务体验；
- 将用户实际流程与竞品能力逐步对照；
- 明确“已有功能”“功能组合差异”和“尚未验证的机会”。

### 阶段 C：产品定义与原型

只有在需求证据支持后，才进入原型阶段。建议用 6—8 屏原型模拟：

1. 内容来源与片段上下文；
2. 保存观点片段；
3. 编辑个人观点卡片；
4. 围绕片段发起或加入讨论；
5. 阅读讨论并记录观点变化；
6. 将观点与另一条内容关联；
7. 回看个人观点；
8. 必要时展示来源与引用信息。

最终屏幕数量和功能应按验证结果调整，不要求为了凑齐流程而保留无价值步骤。

### 阶段 D：可用性测试

邀请至少 5 名目标用户完成“遇到观点 → 保存 → 表达个人理解 → 参与讨论 → 回看/关联”的代表性任务。

记录任务完成情况、耗时、错误、用户自行解释的价值、退出原因和改进建议。不要仅以主观满意度判断产品成立。

## 6. 第一轮关键判断

研究结束后至少回答：

- 痛点发生在哪个具体时刻：内容消费中、消费后，还是未来回顾时？
- 用户最需要保存的是原始片段、自己的想法，还是他人的回应？
- 小宇宙评论与 flomo/Readwise 等工具的组合是否已经足够？
- 小规模讨论是否真的比公开评论或熟人分享更有价值？
- 用户是否愿意为此增加一个独立入口？触发重复使用的条件是什么？
- 哪些功能是核心闭环，哪些只是锦上添花？

## 7. 阶段出口

进入产品定义阶段前，应至少具备：

- 可复述且有真实事件支持的问题陈述；
- 明确的目标用户和使用场景；
- 用户现有替代方案与具体不足；
- 核心竞品现状及其已覆盖能力；
- 对关键假设的支持证据、反例和剩余不确定性；
- 一个范围受控、可测试的 MVP 方案。

当前计划中的样本量和原型任务是探索性研究安排，不是已完成结果。
