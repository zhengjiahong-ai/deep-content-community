# 竞品研究框架

> 版本：v1.0（初始版）  
> 日期：2026-11-07  
> 核心竞品已选定：小宇宙

## 1. 竞品组合与研究角色

### 核心竞品：小宇宙

小宇宙是本项目最贴近的核心竞品。它覆盖播客内容发现、收听、订阅和单集互动讨论，且有创作者与听众之间的平台关系，适合用于课程要求中的完整商业模式画布及总体评估。

研究时必须正视其已存在的时间点评论、评论互动和内容社区能力。项目不能以“用户没有地方评论播客”为未经核实的问题陈述。

### 辅助竞品与参照

| 产品 | 研究角色 | 重点观察 |
| --- | --- | --- |
| Snipd | 播客内容捕捉与知识处理参照 | 高亮、转录、摘要、搜索、向外部知识库同步 |
| Readwise | 多来源摘录和复习参照 | 多平台摘录汇集、阅读回顾、知识复用 |
| flomo | 个人轻量思考记录参照 | 快速记录、标签/关联、回顾机制 |
| 豆瓣 | 兴趣内容讨论参照 | 内容条目、评价、主题小组和讨论氛围 |

辅助产品不一定是直接商业竞品。分析时应按用户任务和价值链区分，不应简单把所有产品放在同一功能表中排名。

## 2. 核心对比维度

| 维度 | 需要回答的问题 |
| --- | --- |
| 核心用户任务 | 用户打开产品主要为了完成什么？ |
| 内容入口 | 内容由平台提供，还是用户从外部导入？ |
| 最小内容单元 | 单集、整篇文章、摘录、时间点、观点卡片还是主题？ |
| 来源上下文 | 用户能否追溯到原始内容、时间点或页码？ |
| 个人表达 | 用户能否把自己的观点与原始摘录分开保存？ |
| 讨论机制 | 是否支持评论、回复、小组讨论或邀请式讨论？ |
| 跨内容关联 | 用户能否把多个来源的观点连接起来？ |
| 回顾与检索 | 旧内容是否能被重新找到和使用？ |
| 商业模式 | 免费服务、订阅、广告、付费内容或其他收入如何构成？ |
| 关键成本与资源 | 内容、技术、云服务、AI、创作者、社区治理和获客分别需要什么？ |

## 3. 小宇宙核心竞品审计清单

应在真实 App 中逐项完成并留存截图或操作记录：

- [ ] 新用户注册与首次使用；
- [ ] 节目发现、搜索、订阅和收听；
- [ ] 时间点评论的创建、展示和回复；
- [ ] 评论点赞、高能片段或其他互动入口；
- [ ] 收藏、历史记录和个人内容管理；
- [ ] 从评论/收藏回到原始内容的路径；
- [ ] 节目主理人、听众和品牌之间的互动；
- [ ] PLUS、付费内容、广告或其他可见变现方式；
- [ ] 用户是否能跨单集组织自己的观点；
- [ ] 当前产品是否存在能替代本项目核心流程的功能。

每项记录核验日期、App 版本、地区/平台、操作步骤和观察结果。无法实际验证的内容应标为“待核实”。

## 4. 辅助竞品审计清单

- [ ] Snipd：如何保存播客片段？来源和时间点是否保留？AI 功能是否需要付费？导出到哪些工具？
- [ ] Readwise：如何汇集不同来源的摘录？复习机制如何触发？如何处理用户自己的观点？
- [ ] flomo：快速记录是否足够轻？如何回顾旧笔记？关联和检索如何工作？
- [ ] 豆瓣：讨论是围绕内容条目还是主题展开？如何维持社区秩序？用户观点如何被沉淀？

## 5. 差异化研究命题

当前值得验证的机会不是“增加评论”或“增加 AI 摘要”，而是：

> 能否把内容原片段、个人观点、小规模讨论和跨内容关联连接成一个连续流程？

这条命题必须与用户真实行为和竞品实际能力逐项对照。若现有产品组合已经充分解决问题，应如实承认，不应把功能组合差异包装成不存在的市场空白。
