# 研究证据与引用规范

> 版本：v1.0（初始版）  
> 日期：2026-11-07

## 1. 结论标签

团队内部研究材料统一区分三类陈述：

- **事实（FACT）：**可由明确来源直接支持，例如官方产品页面展示的功能、公开报告中的统计数字、受访者描述的真实行为。
- **推断（INFERENCE）：**基于一个或多个事实形成的解释或判断，应写明推理链和适用范围。
- **假设（HYPOTHESIS）：**尚未验证的产品、用户或商业模式设想，必须写明如何验证。

建议在研究记录中使用 `[FACT]`、`[INFERENCE]`、`[HYPOTHESIS]` 标签。正式课程报告可以改用自然语言，但不能混淆三者。

## 2. 证据优先级

按结论类型选择证据，不机械地认为某一类来源永远优先：

1. **一手产品证据：**实际 App 操作、官方功能说明、官方定价和服务条款；
2. **原始研究与公开数据：**学术论文、政府统计、监管文件、行业原始报告；
3. **可靠媒体调查：**用于补充市场动态、争议和行业事件；
4. **用户访谈与可用性测试：**用于理解具体行为、动机、替代方案和体验；
5. **团队推断：**必须说明依据，不得伪装成外部事实。

企业宣传材料可以证明“企业公开宣称了什么”，不能单独证明其服务质量、用户满意度或商业表现。

## 3. 来源记录字段

每条重要证据至少记录：

| 字段 | 说明 |
| --- | --- |
| Evidence ID | 唯一编号，如 E-001 |
| Claim | 该证据支持的具体陈述 |
| Type | FACT / INFERENCE / HYPOTHESIS |
| Source | 标题、机构/作者、来源类型 |
| URL | 可直接访问的稳定链接 |
| Published at | 发布日期；未知时写“未标明” |
| Accessed at | 实际访问日期 |
| Scope | 数据覆盖的人群、地区、时间或产品版本 |
| Limitation | 样本、口径、宣传属性或其他局限 |
| Used in | 对应报告章节或决策 |

## 4. 数字与统计口径

- 每个数字都必须带来源、时间和统计口径；
- 不把下载量、注册量、活跃用户数、付费用户数混为一谈；
- 不将小样本访谈结果写成总体比例；
- 不将开发者自报收入写成经审计财务数据；
- 不用行业规模增长直接证明目标用户的具体痛点；
- 不把相关性写成因果关系。

## 5. 竞品研究

- 记录实际测试日期、平台、版本、地区和操作路径；
- 区分“官方宣称具备”“实际体验可用”“用户反馈存在”；
- 功能缺失的判断必须说明检查路径，不能仅因没有找到就写“没有”；
- 竞品价格、订阅权益、功能边界等动态信息必须重新核验；
- 对辅助竞品说明其对应的用户任务，不把它们全部误称为直接竞品。

## 6. 用户访谈

- 以最近一次具体行为为中心，不以抽象态度问题代替行为证据；
- 保留原始表达和必要上下文，分析时再归纳；
- 使用 U01、U02 等匿名编号；
- 记录反例、矛盾和不支持产品方向的证据；
- 不未经同意公开姓名、联系方式、录音或其他可识别信息；
- 用户表达“喜欢”不等于愿意使用，更不等于愿意付费。

## 7. 正式报告引用

- 正文结论与脚注来源必须一一对应；
- 引用应落在实际支持该结论的句子之后；
- 尽量使用原始来源，而非多层转载；
- 对来源无法访问、来源质量不足或数据口径不明的结论降低确定性；
- 历史研究文档中的临时检索标记不能直接作为正式报告脚注，必须替换成可追溯的标题、机构、日期和 URL。

## 8. 研究质量底线

报告应同时呈现支持证据、反向证据和局限。若某项结论目前只能得到推断或假设支持，应明确说明“尚待验证”，不要用确定语气包装。
