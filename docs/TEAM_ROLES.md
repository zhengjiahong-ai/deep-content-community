# 团队分工与协作约定

> 团队规模：4 人  
> 建立日期：2026-11-07  
> 说明：现有讨论确认了四类职责，但尚未提供成员姓名。本文件先记录角色槽位，不猜测或代填姓名。

## 1. 角色分工

| 角色槽位 | 主要职责 | 主要交付 |
| --- | --- | --- |
| 成员 1：组长 / 项目统筹 | 产品战略、项目范围、MVP、商业模式主线、任务协调、冲突裁定与最终整合 | 项目章程、产品定义、最终整合稿、进度与决策记录 |
| 成员 2：用户研究负责人 | 访谈对象招募、访谈执行、用户行为与需求分析、用户旅程整理 | 访谈提纲、去标识化记录、需求证据表、用户旅程 |
| 成员 3：竞品研究负责人 | 小宇宙核心竞品体验、辅助竞品对比、商业模式画布、竞品资料核验 | 竞品体验记录、竞品对比表、小宇宙 BMC、竞品证据 |
| 成员 4：行业与战略研究负责人 | 商业模式外部环境、SWOT、蓝海四项行动与结果画布 | 外部环境分析、SWOT、ERRC 表、结果 BMC |

成员姓名、具体联系方式和最终任务认领由团队补充。若某项工作需要多人协作，应明确一名主责人，避免“共同负责”导致无人跟进。

## 2. 协作原则

1. **先记录证据，再形成结论。**访谈原话、产品实测、公开资料和团队推断应分开记录。
2. **一个交付物对应一个主责人。**其他成员可以提供输入和复核，但主责人负责按时整合。
3. **重大结论需要交叉复核。**尤其是竞品功能、价格、用户规模、商业模式和政策信息。
4. **反向证据必须保留。**发现某个假设不成立时，应更新产品方向，而不是删除不利材料。
5. **统一版本。**仓库中的文档是团队共享的当前版本；重要决策写入决策日志。
6. **引用可追溯。**公开资料记录标题、发布机构、发布日期、访问日期和链接；访谈资料记录编号与日期并去标识化。

## 3. 建议的协作接口

- 用户研究负责人向产品统筹提交：用户原始行为、主要任务、痛点频率、替代方案和反例。
- 竞品研究负责人向产品统筹提交：小宇宙现有能力、关键流程、商业模式证据和辅助竞品边界。
- 行业与战略研究负责人接收已确认的产品问题和竞品范围，再开展外部环境、SWOT 与蓝海分析。
- 产品统筹负责把用户证据、竞品事实和战略分析汇总成一致的产品定义与最终课程报告。

## 4. 任务状态约定

建议统一使用以下状态：

- `TODO`：尚未开始；
- `IN_PROGRESS`：正在进行；
- `BLOCKED`：存在阻塞，需说明原因和依赖；
- `REVIEW`：已提交，等待复核；
- `DONE`：完成并已确认。

每次团队会议后更新负责人、交付物、截止时间和阻塞项。
